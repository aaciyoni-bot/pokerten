## Timing changes

The old rendering loop also drove network polling and eased confirmed prices. Slow animation frames therefore delayed both the readout and the graph. A browser trace reproduced a last displayed 7.14x followed by an 11.88x stop.

The new authenticated server stream emits signed prices about 20 times per second. Networking and readout updates run independently of animation frames. The server sends the final price at the phase deadline before waiting for all bet settlement writes. Client prices cannot exceed the latest approved price; stale connections freeze explicitly.

Firestore's actual location was verified as `eur3`. New AVIATOR services run in `europe-west1`, near that database. The original `us-central1` callables remain for existing clients. No minimum-instance billing was enabled; an authenticated no-op warms the cashout service during boarding. Bet reads are batched.

The manual acceptance rule remains server arrival strictly before the crash, with a valid signed quote. Arrival at the boundary loses. An earlier reached automatic target takes precedence. Accepted manual receipts pay the captured submitted hundredths and whole-chip payout exactly. Request IDs prevent duplicate debits and credits. Client responses cannot change a later round. No probabilities or house-edge rules changed.

## Measured production results

The final GitHub runner probe received 571 price packets: interval median 51 ms, p95 54 ms. Across nine distinct rounds, first server stop announcements were 1–3 ms after the scheduled deadline. A later reconnect repeated one already-ended round at 1,581 ms; that duplicate is not an initial stop announcement. These are server/runner measurements, not the player's network latency.

Manual 101-chip probe receipts: 1.13x paid 114 chips (290 ms), 1.03x paid 104 (263 ms), and 1.01x paid 102 (263 ms). Server processing was 87–108 ms. A stored automatic 1.20x target paid 121 chips without a manual request. Duplicate calls caused no additional debit or credit; wallet and bet records were checked using that test account's own authentication.

The supported browser then tested the real production domain:

- 101-chip bet: balance 9,596 → 9,495.
- Immediate pending UI captured and displayed 1.02x.
- Confirmed receipt: 1.02x, +103 chips, measured request/acknowledgement time 524 ms.
- Final wallet display: 9,598; player row showed the same 1.02x exit.
- Natural 1.00x rounds stopped immediately without a speculative flight.
- An earlier 1.04x attempt near a natural 1.06x crash was not credited. Requests are not guaranteed to arrive before a crash merely because input began before the browser received the stop.

Before production, the European preview also confirmed 101 chips at 1.04x → 105 chips in 443 ms. Browser automation has input-dispatch overhead: pending UI records the actual input price; an earlier DOM snapshot is not the click timestamp. No zero-latency claim is made.
