# Release 337

A positive per-user payout now selects applause for that user, including every split-pot, side-pot and multiple-board recipient. Other players and spectators hear a separate 0.78-second soft ta-da. A table opened after the result, or resumed from a headless view, does not replay the result. Existing imported applause samples and original-theme rollback remain intact.

The installed web app checks releases without waiting for service-worker registration, retries on foreground/network/controller changes, and times out stalled requests. Explicit reloads verify the fetched HTML version, preserve navigation parameters and refuse to interrupt a table. The recovery page at `/update.html` offers the same refresh without clearing sign-in, preferences or game data. Hosting sends no-store headers for the app shell and update configuration. Service-worker cleanup is limited to PokerTen shell caches.

Validation: 20 predeploy checks, generated worker/UI checks, 91 unit tests and the complete simulated UI suite passed locally. The actual browser audio engine decoded the existing 6.00-second applause and played the separate 0.78-second cue with a running AudioContext. No live account, game or balance mutations were used. Deployment validation and production UI checks follow before release completion.

An app window already running an older release may still need to be fully closed and reopened once. Native APK installation was not confirmed; device-specific update delivery is not claimed.
